# Studio Proof Standard

A studio proof is not a release preview dressed up as a download. It is a testable artifact built to answer a specific design question.

## A proof must include

- A precise question the test is meant to answer.
- A version number and date.
- A printable or usable artifact at the intended scale.
- A short test protocol.
- A way to record what worked, what failed, and what should change.
- A clear statement that the proof is not an approved agency record or finished Forge & Verse release.
- SHA-256 values for the package contents.

## Data caution

Proofs intended for public download must instruct users to use fictitious or sanitized information unless their agency has approved a controlled test. No proof should encourage the entry of CJI, case-sensitive data, credentials, or restricted material into a public service.

## Progression

A concept can move from Sample to Ready only after the proof answers the release test with real use rather than visual preference alone.

## Naming

Use `Field Test` for a proof that needs real workflow use. Use `Material Sample` for a physical-production test. Use `Composition Study` for an art layout that has not yet entered physical production.
