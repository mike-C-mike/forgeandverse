# Archive Policy

## Current releases

Only the current approved public bundle and its component files remain in the active download tree unless an older release is intentionally retained for compatibility or historical research.

## Superseded releases

When a release is superseded:

1. keep the version history on the release page
2. remove obsolete bundle links from public layouts
3. remove superseded files from `static/downloads/`
4. rebuild the release ledger
5. update checksums and manifests
6. retain source material only when it remains useful for future development

## Rejected concepts

A rejected or unearned release should be removed from content and public assets. It should not stay visible merely because files already exist.

## Resting physical editions

A physical edition can remain in the Work archive with `edition.state: resting`. The page preserves the work and its specification while showing no active ordering link.

## Git history

Git history is the technical archive. The public static directory is not required to preserve every file ever released.
